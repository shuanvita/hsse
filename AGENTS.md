# Правила проекта

## Архитектура

Проект использует Nuxt и организацию кода по принципам Feature-Sliced Design (FSD). Исходный код находится в `src/`.

- `app/` — инициализация приложения, layouts, глобальные стили и файловые маршруты Nuxt. Маршрут в `app/routes/` подключает соответствующую страницу через её публичный API.
- `pages/` — композиция страниц и данные, относящиеся к конкретной странице. Страница собирает виджеты и передаёт им данные.
- `widgets/` — самостоятельные крупные блоки интерфейса. Код конкретного виджета хранится в собственном слайсе; при необходимости виджеты группируются по странице, например `widgets/home/hero/`.
- `features/` и `entities/` — при необходимости добавляются для пользовательских действий и бизнес-сущностей соответственно. Не создавайте пустые слои заранее.
- `shared/` — общие UI-компоненты, утилиты и ресурсы без привязки к странице или бизнес-сущности.

Зависимости направляйте сверху вниз: `app → pages → widgets → features → entities → shared`. Слайсы одного слоя не должны зависеть друг от друга; общий код переносите в подходящий нижний слой. Внешние потребители импортируют слайс через его `index.ts`, внутренние файлы слайса могут использовать относительные импорты. Не вводите обходные зависимости через `app`.

## Компоненты

- Используйте Vue SFC с `<script setup lang="ts">`, семантическую разметку и существующие общие компоненты `Ui*`, когда они подходят.
- Для виджета или страницы размещайте компоненты в `ui/`, типы и данные — в `model/`, публичные экспорты — в `index.ts`. Выделяйте файлы и сегменты по мере необходимости, не создавая пустые папки.
- Для компонентов `shared/ui` придерживайтесь существующей структуры: `Component.vue`, при необходимости `Component.types.ts`, `Component.constants.ts` и `index.ts`. Типизируйте props, задавайте значения по умолчанию через `withDefaults`, повторяющиеся варианты классов выносите в constants.
- Передавайте данные через типизированные props, используйте события и слоты для взаимодействия. Внутренние подкомпоненты оставляйте в слайсе и экспортируйте наружу только необходимый API.
- Используйте существующие стили и Tailwind-классы проекта; сохраняйте доступность интерактивных элементов и осмысленный альтернативный текст изображений.
- Поддерживайте чистоту вёрстки и классов: избегайте ненужных обёрток, дублирующих и конфликтующих классов и значений, уже заданных стилями компонента или базовыми стилями. Перед удалением проверяйте каскад, адаптивность и доступность.
- Для HTML, выводимого через `v-html`, используйте существующий `sanitizeHtml`. Текст типографируйте через `typograf` из `~/shared/lib/typograf`; не применяйте его к URL и путям ресурсов.

### Создание компонента

1. Определите слой по назначению: универсальный интерфейсный элемент помещайте в `shared/ui`, самостоятельный блок страницы — в `widgets`, композицию блоков — в `pages`. Логику конкретного layout оставляйте в `app/layouts`.
2. Создавайте только необходимые файлы. Для страницы или виджета это обычно `ui/Component.vue` и `index.ts`; при наличии контракта или данных добавляйте `model/Component.types.ts` и `model/Component.data.ts`. Внутренние подкомпоненты размещайте рядом в `ui/`.
3. Для общего компонента используйте каталог `shared/ui/component/` с `Component.vue` и `index.ts`. Вынесите типы в `Component.types.ts`, а повторяющиеся наборы классов и варианты — в `Component.constants.ts`, когда это оправдано сложностью компонента.
4. Опишите входные данные через TypeScript, необязательные значения по умолчанию задавайте через `withDefaults`. Для взаимодействия используйте типизированные события и слоты; состояние держите в том компоненте, который им управляет.
5. В `index.ts` экспортируйте компонент и только те типы, которые необходимы внешним потребителям. Не импортируйте внутренние файлы другого слайса напрямую. Общие компоненты, подходящие под автоматическую регистрацию Nuxt, можно использовать в шаблонах как `Ui*`.

### Данные страниц и виджетов

- Данные, специфичные для страницы, храните в её `model/`, например `pages/home/model/HomePage.data.ts`. Для каждого блока формируйте именованный объект по контракту соответствующего виджета: импортируйте тип props через публичный `index.ts` виджета и типизируйте объект этим типом.
- Страница импортирует данные из своего `model/`, компонует виджеты и передаёт им подготовленные значения через props. Когда объект данных соответствует контракту props, используйте `v-bind="имяОбъекта"`; отдельные значения передавайте явно, если так понятнее.
- Виджет определяет собственный контракт в `model/Component.types.ts`, принимает данные через `defineProps` и передаёт необходимые части внутренним компонентам через их типизированные props. Массивы отображайте с устойчивыми ключами; взаимодействия возвращайте наверх через события или `v-model`.
- Данные, принадлежащие самому виджету и не зависящие от страницы, можно хранить в его `model/Component.data.ts` и использовать внутри слайса, как данные общей шапки. Не импортируйте данные страницы в виджет: они передаются сверху вниз.
- При подготовке данных типографируйте пользовательский текст через `typograf`, а ссылки и пути к изображениям сохраняйте без обработки. Не дублируйте типы данных на странице, если контракт уже экспортируется виджетом.

## Проверка

Проверяйте изменённые файлы ESLint и запускайте сборку, когда изменение затрагивает интеграцию приложения. Учитывайте существующие незакоммиченные изменения и не перезаписывайте их без необходимости.
